================================================================================
RINGKASAN
================================================================================
Barang = unit fisik hasil produksi. Relasi:
  Product (1) -> ProductVariant (N) -> Barang (N)
  ProductionBatch (1) -> Barang (N)
  Barang (1) -> RiwayatBarang (N)

CRUD classic yang ditambahkan (selain generate/status/scan yang sudah ada):
  POST   /api/barang       -> Create single barang (manual atau auto-generate kode)
  GET    /api/barang       -> List + filter + pagination (sudah ada)
  GET    /api/barang/:id   -> Detail by ID (sudah ada)
  PUT    /api/barang/:id   -> Update barang
  DELETE /api/barang/:id   -> Hapus barang

Auth: saat ini TIDAK memakai middleware auth (sesuai src/app.ts & src/routes/barang.ts).
Format body: JSON. Semua response JSON.

================================================================================
MODEL & ENUM
================================================================================
Model Barang (prisma/schema.prisma):
  id         Int @id autoincrement
  kodeBarang String @unique  // format: BC{batch3}-{kodeVariant}-{DDMMYY}-{urut4} ex: BC001-W001-250826-0001
  variantId  Int             // FK ProductVariant (Restrict)
  batchId    Int?            // FK ProductionBatch (Restrict, nullable)
  tanggal    DateTime?       // default now()
  status     StatusBarang @default(REGISTER)
  createdAt  DateTime
  updatedAt  DateTime

StatusBarang:
  REGISTER | FINISHGOOD | RETUR | OUT | BAD

Transisi valid (VALID_TRANSITIONS di barang.status.ts):
  REGISTER   -> FINISHGOOD | OUT | RETUR | BAD (atau tetap REGISTER)
  FINISHGOOD -> OUT | RETUR | BAD
  RETUR      -> FINISHGOOD | OUT | BAD
  OUT        -> terminal (tidak bisa pindah)
  BAD        -> terminal

Batch:
  nomorBatch Int @unique, totalProduksi Int, kapasitas Int default 5000, status AKTIF|SELESAI

================================================================================
1. CREATE BARANG - POST /api/barang
================================================================================
Handler: createBarangHandler (src/controller/barang/crud.controller.ts:16)
Model:   createBarang (src/model/barang/barang.crud.ts:43)
Route:   router.post("/", createBarangHandler) (src/routes/barang.ts:44)
Broadcast WS: type "barang.created"

Request Body (JSON):
{
  "variantId": 1,              // required, number, harus ada di ProductVariant
  "batchId": 1,                // optional, number|null. Jika null/omit -> pakai batch AKTIF atau buat BC001
  "kodeBarang": "BC001-W001-250826-0001", // optional, string. Jika omit/kosong -> AUTO-GENERATE
  "tanggal": "2026-09-03T00:00:00.000Z",   // optional, ISO/ YYYY-MM-DD, default now()
  "status": "REGISTER",        // optional, salah satu StatusBarang, default REGISTER
  "keterangan": "Barang dibuat (manual)" // optional, string, disimpan ke RiwayatBarang
}

Validasi:
  - variantId wajib angka dan variant harus ada -> 404 "Variant tidak ditemukan"
  - batchId jika diisi harus angka dan batch harus ada -> 404 "Batch tidak ditemukan"
  - status jika diisi harus valid -> 400
  - kodeBarang jika diisi harus string unik -> 409 "Kode barang sudah ada"
  - tanggal jika diisi harus valid Date -> 400

Logic auto-generate (jika kodeBarang tidak diisi):
  1. Tentukan targetBatch:
     - Jika batchId diisi -> pakai batch itu
     - Jika tidak -> SELECT ... FOR UPDATE batch AKTIF desc, jika tidak ada buat nomorBatch=1, jika penuh (totalProduksi >= kapasitas) -> update SELESAI + create batch baru nomor+1
  2. Allocate BarangCounter FOR UPDATE where (batchId, variantId, tanggal dateOnly):
     - jika belum ada -> create currentCount=1, nomorUrut=1
     - jika ada -> nomorUrut = currentCount+1, update currentCount
  3. Generate kode: BC{pad3(nomorBatch)}-{kodeVariant}-{DDMMYY}-{pad4(nomorUrut)}
  4. Transaction: create barang + create riwayatBarang + increment productionBatch.totalProduksi (dan set SELESAI jika penuh)

Logic manual kodeBarang:
  - Transaction: create barang + create riwayatBarang + increment batch.totalProduksi jika batchId ada
  - Counter TIDAK diupdate (karena kode manual)

Response 201:
{
  "id": 101,
  "kodeBarang": "BC001-W001-030926-0001",
  "variantId": 1,
  "batchId": 1,
  "tanggal": "2026-09-03T00:00:00.000Z",
  "status": "REGISTER",
  "createdAt": "...",
  "updatedAt": "...",
  "variant": { "id": 1, "kodeVariant": "W001", "product": {...}, "style": {...}, "color": {...}, "size": {...} },
  "batch": { "id": 1, "nomorBatch": 1, "totalProduksi": 101, "kapasitas": 5000, "status": "AKTIF" }
}

Error:
  400 - Field 'variantId' wajib diisi dan berupa angka
  400 - Field 'tanggal' harus tanggal valid
  400 - Field 'status' harus salah satu dari: REGISTER, FINISHGOOD, RETUR, OUT, BAD
  404 - Variant tidak ditemukan / Batch tidak ditemukan
  409 - Kode barang sudah ada
  500 - Gagal membuat barang

Contoh cURL:
  # Auto-generate
  curl -X POST http://localhost:3000/api/barang -H "Content-Type: application/json" -d "{\"variantId\":1}"

  # Manual kode
  curl -X POST http://localhost:3000/api/barang -H "Content-Type: application/json" -d "{\"variantId\":1,\"batchId\":1,\"kodeBarang\":\"CUSTOM-001\",\"status\":\"REGISTER\"}"

4. UPDATE BARANG - PUT /api/barang/:id
================================================================================
Handler: updateBarangHandler (src/controller/barang/crud.controller.ts:85)
Model:   updateBarang (src/model/barang/barang.crud.ts:255)
Route:   router.put("/:id", updateBarangHandler) (src/routes/barang.ts:77)
Broadcast WS: type "barang.updated"

Params: id number

Request Body (minimal 1 field wajib):
{
  "variantId": 2,              // optional, number
  "batchId": 2,                // optional, number|null (null untuk lepas dari batch)
  "kodeBarang": "BC001-W001-030926-0002", // optional, string unik
  "tanggal": "2026-09-04T00:00:00.000Z",   // optional, Date
  "status": "FINISHGOOD",      // optional, StatusBarang (divalidasi transisi)
  "keterangan": "Update via PUT" // optional, dipakai jika status berubah -> masuk RiwayatBarang
}

Validasi:
  - minimal satu dari variantId/batchId/kodeBarang/tanggal/status harus ada -> 400
  - variantId jika ada harus ada di DB -> 404
  - batchId jika ada harus ada di DB -> 404, null diperbolehkan
  - kodeBarang jika ada harus unik (kecuali milik sendiri) -> 409
  - tanggal harus valid -> 400
  - status harus valid dan transisi dari status sekarang harus diperbolehkan (lihat VALID_TRANSITIONS) -> 400 "Transisi status dari X ke Y tidak valid"
  - id harus angka -> 400, barang harus ada -> 404

Logic batch:
  - Jika batchId berubah (old != new) -> transaction decrement oldBatch.totalProduksi dan increment newBatch.totalProduksi

Logic status:
  - Jika status berubah -> update barang.status + create riwayatBarang baru

Transaction: update barang + adjust batch + create riwayat (jika perlu)

Response 200: objek barang updated (sama seperti create)

Error:
  400 - Minimal satu field harus diisi / Field tidak valid / Transisi tidak valid
  404 - Barang tidak ditemukan / Variant/Batch tidak ditemukan
  409 - Kode barang sudah ada

cURL:
  curl -X PUT http://localhost:3000/api/barang/101 -H "Content-Type: application/json" -d "{\"status\":\"FINISHGOOD\",\"keterangan\":\"QC pass\"}"
  curl -X PUT http://localhost:3000/api/barang/101 -H "Content-Type: application/json" -d "{\"variantId\":2,\"batchId\":2}"

================================================================================
5. DELETE BARANG - DELETE /api/barang/:id
================================================================================
Handler: deleteBarangHandler (src/controller/barang/crud.controller.ts:172)
Model:   deleteBarang (src/model/barang/barang.crud.ts:369)
Route:   router.delete("/:id", deleteBarangHandler) (src/routes/barang.ts:80)
Broadcast WS: type "barang.deleted"

Params: id number

Logic:
  - Cari barang, jika tidak ada -> 404
  - Transaction:
      deleteMany riwayatBarang where barangId=id  (karena FK Restrict)
      delete barang where id=id
      jika barang.batchId ada -> decrement productionBatch.totalProduksi by 1
  - Catatan: BarangCounter TIDAK didecrement (counter tetap)

Response 200:
{ "message": "Barang berhasil dihapus", "id": 101 }

Error:
  400 - Parameter 'id' tidak valid
  404 - Barang tidak ditemukan
  500 - Gagal menghapus barang

cURL:
  curl -X DELETE http://localhost:3000/api/barang/101
